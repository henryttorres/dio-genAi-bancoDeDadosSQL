Da planilha estática à observabilidade contínua

O projeto reduz a cegueira temporal, registra o estado da operação e organiza as informações necessárias para decisões de prospecção mais rápidas, rastreáveis e seguras.

01. Engenharia de Dados

Ingestão e normalização

Importação CSV, preparação para API, padronização de datas, horários, praças, lojas, turnos e vagas.

02. Operação

Motor de regras

Validação de elegibilidade, soma por praça e recomendação transparente entre Blip Desk e Blip Portal.

03. Experiência

CX humanizado

Guardrails para comunicações claras, acolhedoras e baseadas somente em informações efetivamente validadas.

Fluxo arquitetural

Uma arquitetura progressiva, preparada para evoluir do MVP local até uma camada preditiva.

CSV ou API → Python → Normalização → Snapshots e eventos → Sheets/Banco → Grafana → Motor de decisão → Blip

Regras operacionais do MVP

O turno precisa possuir vagas e mais de 1h30 até o encerramento. A decisão considera a soma das lojas elegíveis da mesma praça e do mesmo dia.

0

Sem vagas

Não acionar.

1 a 2

Vagas elegíveis

Segurança e uso responsável

Nenhum dado pessoal, token, credencial, chave de API ou informação corporativa restrita deve ser publicado. O MVP recomenda ações, mas mantém a validação humana antes de qualquer comunicação.
