Prompt Sênior: Arquitetura de Dados e Previsibilidade Logística

Atue como um Engenheiro de Dados Sênior e Arquiteto de Soluções de Inteligência Artificial.

Sua tarefa é analisar o fluxo de dados do processo de prospecção de entregadores no projeto "Rodar em Loja" (iFood) para identificar o modelo ideal de transição de um ecossistema de registros manuais para uma arquitetura de banco de dados orientada a eventos (time-series).

Contexto: Atualmente, a operação de prospecção é registrada manualmente em uma planilha estática, geralmente com verificações às 16:00. No entanto, a disponibilidade de vagas (slots) logísticos é altamente volátil: novas lojas abrem vagas e entregadores cancelam agendamentos de última hora (churn) continuamente. O modelo manual atual gera retrabalho operacional, conflita com os horários de atendimento simultâneo na plataforma Blip Desk e, principalmente, causa cegueira de dados sobre os picos reais de ociosidade. A análise será usada pela coordenação de operações e pela equipe de dados para justificar a automação da captura desses dados via API do Grafana. O objetivo final de longo prazo é usar essa nova base estruturada para treinar modelos preditivos de Deep Learning que antecipem a abertura de vagas, otimizando o momento exato dos disparos de prospecção.

Dados disponíveis:

Modelo Estático Atual (CSV): Possui colunas de controle manual como Data, Hora (ex: 16:00), Região, Quantidade de slots disponiveis 2h antes, Quantidade de slots disponiveis após iniciar turno, Quantas mensagens disparadas?, e Quantas mensagens com falhas?.

Modelo Dinâmico Alvo (Grafana): Possui metadados em tempo real como inicio_turno, fim_turno, regiao, vagas_solicitadas, vagas_reservadas e vagas_livres.

Instruções de análise:

Compare o custo de oportunidade e a perda de rastreabilidade (dados invisíveis) gerados pela coleta estática às 16:00 em relação à captura contínua do Grafana.

Proponha um novo esquema (schema) de dados transacional focado em Séries Temporais, eliminando as colunas de "verificação manual" e inserindo rastreamento de ciclo de vida da vaga (abertura, preenchimento, cancelamento).

Formule ao menos duas métricas analíticas novas, como "Taxa de Volatilidade de Slots" e "Tempo Médio de Preenchimento".

Sugira uma rota técnica (roadmap) explicando como essa nova estrutura de dados servirá de base alimentar para um modelo de redes neurais recorrentes (como LSTM) para a previsão de demanda.

Formato da resposta:
Entregue um Resumo Executivo conciso da falha arquitetural atual. Em seguida, apresente uma tabela comparativa (De-Para) mostrando as colunas atuais do CSV versus as colunas propostas para o novo Data Warehouse. Finalize com um roadmap estruturado em tópicos descrevendo os passos desde a automação da ingestão (ETL) até o treinamento do modelo preditivo.

Restrições:

Use apenas as estruturas de dados e o cenário logístico fornecidos.

Não invente volumes de dados, números estatísticos ou taxas falsas nas suas explicações; concentre-se na modelagem arquitetural.

Não mencione ou exponha os nomes dos analistas presentes nos dados de origem.

Informe as limitações se a volumetria inicial for um impeditivo momentâneo para o treinamento do Deep Learning.

Use linguagem técnica, direta, com autoridade de engenharia de software, focada em eficiência operacional e ciência de dados.
